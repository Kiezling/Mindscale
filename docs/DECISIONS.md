Record stable decisions that should survive chat resets and model/provider changes. Keep entries short; link to a spec when one exists. If a decision changes, add a superseding entry instead of rewriting history.

## D-004 — Capability-first model routing

- Date: 2026-07-22

## D-012 — Phase 12 local import and restore

- Date: 2026-08-04
- Decision: add exactly two local import actions with separate, never-blended semantics. `Restore from backup` accepts a MindScale JSON backup of version 3, 4, or 5 and replaces every record, the canonical settings row, the canonical Profile row, and all external totals, inserting the file's ids verbatim into emptied tables. `Import records` accepts a MindScale records CSV and only appends ratings, sleeps, and markers. No file may mutate Room until it has been size-limited, strictly UTF-8 decoded, parsed by a hand-written bounded reader, version-checked, structurally and semantically validated, conflict-checked, previewed with exact factual counts and disclosed defaults, and explicitly confirmed. Every malformed, ambiguous, duplicate, conflicting, oversized, unsupported, or future-version file is rejected totally — never skipped, repaired, reinterpreted, truncated, or partially accepted. The approved mutation runs in one Room transaction with six post-mutation checks that roll back on violation. Imported PHQ-8/GAD-7 totals require and re-assert fixed `EXTERNALLY_OBTAINED_USER_ENTERED` provenance and are never scored, compared, or interpreted. Raw file content never enters `SavedStateHandle`. No schema change, migration, downgrade path, dependency, permission, or toolchain change is added. See `docs/specs/SPEC-import-restore.md`, D-1 through D-12.
- Reason: Phase 4 and Phase 11 exports were deliberately one-way, leaving reinstall, device change, and post-erase recovery unsupported. Replace-only JSON and add-only CSV are the smallest coherent semantics that are explainable to a user, and total rejection is the only policy consistent with MindScale's rule that it arranges the user's data without ever reinterpreting it.
- Supersedes: none; resolves the deferral in D-5 of `SPEC-settings-data-control.md` and satisfies the future-import contract required by D-9 of `SPEC-clinician-report-profile.md`.
- Amendment (2026-08-04, non-semantic): `BackupPayload` and `RecordsPayload` are declared in the `data` package rather than `settings` as the spec's frozen-interface block wrote them. Name, fields, and meaning are unchanged; the move only prevents a `data` → `settings` package cycle, because `DataControlDao` accepts these types while every parser already depends on the `data` entities. Recorded here because `AGENTS.md` requires a frozen-interface change to be documented rather than made silently.
- Amendment (2026-08-04, behavioral clarification): an import stops being cancellable once `confirmImport` has started its Room transaction. The spec froze cancellation for the picker and read phases and required writes to be cancellable "before the transaction starts"; clearing the pending state mid-transaction would have reported a cancellation while the mutation completed. Cancel is now a no-op and is visibly disabled while the mutation runs.

## D-013 — Phase 13 native Safety card and personal safety plan

- Date: 2026-08-05
- Decision: add one `SAFETY` overlay holding verified crisis resources and the user's own Stanley-Brown safety plan, stored locally. Preserve all six canonical Stanley-Brown steps in declaration order — warning signs, internal coping, distraction, people to ask for help, professionals, making the environment safe — with plain-language headings mapped one-to-one in the spec. Freeze every crisis string verbatim, including a single 988 block covering the United States and Canada, a Find A Helpline pointer for everywhere else, an emergency sentence with deliberately no button, and a visible verification date. Reach the card only by a user tap from a persistent Track footer link or a Profile row; it is never a pop-up, never auto-navigated to, and its content depends on nothing recorded — `SafetyViewModel` takes `SafetyPlanDao` and nothing else, so no future edit can make it inferential without breaking a frozen interface. Hand phone actions off with `ACTION_DIAL`/`ACTION_SENDTO`/`ACTION_VIEW` built through `Uri.fromParts`, never `ACTION_CALL`, with no `CALL_PHONE` permission, no `<queries>` element, and a caught `ActivityNotFoundException` that leaves the number on screen. Record nothing about opening the card or tapping a resource. Store the plan through additive Room 5→6 and JSON backup version 6; keep the records CSV, the clinician summary, and every share/copy action free of plan content; restore backup versions 3–6 with total rejection unchanged; and disclose exact plan counts in both the restore preview and the erase dialog. See `docs/specs/SPEC-safety-card.md`, D-1 through D-11.
- Reason: this is the first MindScale surface whose content can matter to someone in acute distress, so accuracy, ordering fidelity, and legibility under distress are the product, not the mechanics. A card the user cannot write into would be an inert control and would abandon the intervention's actual evidence base; a card gated or triggered by recorded data would make a measurement instrument look like a risk assessment it is not and must never be.
- Supersedes: none; resolves the Safety half of the backlog's Safety-and-off-ramp item.
- Amendment (2026-08-05, corrective): the spec's frozen `SafetyPlanDao.observeAll()` signature ordered by `step ASC, position ASC`. That is wrong — the step is stored as its enum name, so SQL would order it alphabetically (`DISTRACTION` before `WARNING_SIGNS`), which is not the canonical Stanley-Brown order this phase exists to preserve. The query now orders by `position ASC, id ASC` and canonical step order is applied in Kotlin by `List<SafetyPlanItem>.groupedByStep()`, which is pure and covered by both a JVM and an instrumented test. `DataControlDao.allSafetyPlanItems()` follows the same rule.
- Amendment (2026-08-05, non-semantic): `validatePlanText`/`validatePlanPhone` return a purpose-built `PlanFieldResult` rather than the spec's `Result<String>`. `kotlin.Result`'s failure channel requires a `Throwable`, and a value the user mistyped is not an exception; this matches the `ParseResult` shape Phase 12 already uses for the same reason. Rules, limits, and messages are unchanged.
- Amendment (2026-08-05, copy correction found by installed-app inspection): the restore preview's "It contains …" line initially said "plus your settings, Profile name, and safety plan" for every version. On a real version-5 backup that claimed the file held a safety plan it cannot contain. The clause is now version-conditional, and the deletion sentence reads "your safety plan of N lines" rather than the redundant "N safety plan lines". Pinned by `ImportPreflightTest`.
- Recorded finding (2026-08-05): the "low-frequency off-ramp follow-on" half of that backlog item is already delivered and Phase 13 adds nothing to it. Phase 2 shipped the 40-entry/60-day check-in banner with `Still useful`/`Pause tracking` and the paused banner; Phase 4 shipped the `SettingsFocus.DATA` deep link that makes pause, export, and erase one screen. Adding a Safety link to either banner was considered and rejected: those are the only surfaces whose visibility depends on recorded data, so crisis resources inside them would read as an inference about the user.

## D-014 — Phase 14 optional paced-breathing object

- Date: 2026-08-05
- Decision: add one `BREATHING` overlay holding a single fixed-cadence pacing circle — 4500 ms in, 6500 ms out, an 11 000 ms cycle, 5.45 breaths per minute — with exactly two phases and no configurability, reachable only by a user tap on a Track link shown when `breathingOn` is true and tracking is not paused. Offer exactly 1/3/5/10 minutes with nothing preselected, and start nothing until the user picks. Make no claim anywhere: no efficacy, no science-backing, no protocol name, no citation, no effect size, no therapeutic verb. Record a session whenever the pacer actually ran — on completion, on Stop, and on Back — as `BreathingSession(id, startedAt, endedAt)` holding the real elapsed interval, with no minimum threshold, and store it through additive Room 6→7, JSON backup version 7, and a `breathing` records-CSV row written on the byte-identical Phase 12 header. `BreathingViewModel` takes `BreathingSessionDao` and `BreathingClock` and nothing else, `BreathingSessionDao` exposes only `insert` and `count`, and a source scan plus a constructor-reflection test enforce that no recorded value can ever reach this screen. Breathing data appears in the export, the restore preview, and the erase dialog, and in no other surface. See `docs/specs/SPEC-paced-breathing.md`, D-1 through D-14.
- Reason: the product source keeps the pacer but strips its justification — the same team whose meta-analysis looked promising then ran two placebo-controlled trials that were both null, and STARS found fast equal to slow. So the honest object is a mechanic with no claim attached, and the never-auto-offered rule is a safety rule rather than a taste one: Schmidt 2000 found breathing retraining trending toward poorer outcomes in panic and Barlow discourages respiratory control as a safety behavior, so a pacer keyed to a high rating would be both an inference MindScale does not make and a plausible harm. Recording every session is what keeps a UI object that changes the user's physiology from silently perturbing the measurement it sits next to.
- Supersedes: none; resolves the final scoped item in `docs/specs/BACKLOG.md`.
- Prototype details deliberately rejected, each recorded with its reason: the reference implementation commits a session record **only on natural completion**, so a five-minute session stopped at four minutes stored nothing — that is exactly the silent perturbation the product source warns against, and every session that ran is now recorded. It also ends at the first phase boundary at or after the chosen total, so its "1 min" button runs 66 seconds; a session now ends exactly when the chosen duration elapses so the label is true. Its `{id, ts, minutes}` record is replaced by an interval and the chosen length is **not** stored: elapsed time is the fact, intent is not, and an export legible as "chose 10, managed 2" is an interpretation axiom 4 reserves for the human. Its always-plural running readout ("1 minutes") is corrected. Its cadence, length set, toggle copy, and instruction line are adopted verbatim because they already satisfy the frozen constraints.
- Deliberate divergence from D-013: the Safety link renders unconditionally including while paused, but the breathing link is hidden while paused. A breathing session **writes a dated record**, and pause means the capture surface is hidden, so offering a control that creates records during a pause would contradict what pause means. Both gating conditions are settings the user set, never recorded data.
- Amendment (2026-08-05, non-semantic wording clarification found by critical review): D-9 said the backup's `breathingSessions` array is "ordered by `startedAt` then `id`" without stating a direction. It is **descending** — newest first, matching every other collection in the file and `DataControlDao.allBreathingSessions()`. The implementation was already descending; only the spec sentence was loose, and it is now explicit so a future re-implementation cannot read it the other way and silently break byte-reproducible re-export.
- Amendment (2026-08-05, corrective, found by critical review): `BreathingViewModel` gained `discardSession()`, which ends a running session and writes nothing, and `MindScaleApp`'s erase/restore effect now calls it instead of `leaveScreen()`. `leaveScreen()` records the partial session, which is right for Back but wrong immediately after an erase: the user has just asked for everything to be deleted, so completing that write would put a row back into a table the transaction had already cleared. No in-app path currently reaches the erase dialog from the breathing screen, but the fix deliberately does not depend on that navigation topology holding in future.
- Explicitly out of scope with reasons recorded in the spec: no haptic or audio pacing cue in any form, because a vibration or tone pattern is a portable technique that outlives the screen and is the respiratory-control safety behavior Barlow warns about; no Insights or Full Log surface, because a chart placing sessions beside intensity would manufacture the causal inference two placebo-controlled trials failed to support; no per-session delete, no streak, count, total, or history list.

## D-015 — Phase 15 brand token foundation and app chrome

- Date: 2026-08-05 (merged 2026-08-06)
- Decision: scope the visual overhaul as four phases, 15 through 18, all governed by one rule — **the phases change how the app looks and nothing about how it works** — and deliver the foundation in Phase 15. Install the complete palette taken literally from `MindScale v2.dc.html`, a four-level ink emphasis scale, all 47 Material 3 colour roles, all 15 Material text styles in bundled Instrument Sans, the shape scale passed to `MaterialTheme` for the first time, a spacing scale, a shared presentation-only component layer, and the app chrome: a flat three-cell header with the wordmark treatment, a text-only bottom navigation, a full-bleed Breathing overlay, and the nine dialogs routed through one gold-bordered container. See `docs/specs/SPEC-visual-foundation.md`, D-1 through D-25.
- Reason: the app was built from the Claude Design prototype but only ever adopted its behavior, never its visual identity. `SPEC-full-log.md` D-9 deferred "the shared gold/ink light/dark token foundation until the later global brand phase, when it can be applied consistently to every screen. Do not implement a one-screen-only pseudo-theme." This is that phase. The starting state was 13 of the colour roles set, 1 of 15 text styles overridden and naming `FontFamily.Default`, shapes never passed to `MaterialTheme`, 246 hardcoded dimension literals, and no shared component layer.
- Supersedes: nothing. Discharges `SPEC-full-log.md` D-9 and replaces the backlog's unscoped "later UI overhaul" note with four specified phases.
- The visual-only rule is objective, not aspirational: **206/206 connected and 399/399 JVM tests pass with no pre-existing test file modified.** A broken test would be evidence that behavior changed, which is a defect in the phase rather than a test to update. `git diff --name-status 009f334 HEAD` over both test trees shows four additions and zero modifications.
- Case is presentation, never semantics. The design uppercases nearly every label and 111 `onNodeWithText` assertions across 8 connected test files depend on the original case, so `MsUppercaseText` renders `uppercase(Locale.ROOT)` and restores the original through **`clearAndSetSemantics`**, not `semantics` — the `Text` key merges by appending, so a plain block would leave both strings on the node and a control would read its own label twice. `Locale.ROOT` is deliberate: under a Turkish default an `i` becomes a dotted capital and the label changes meaning. Proved by six connected tests before anything depended on it.
- Accessibility outranks the prototype, and every divergence is measured rather than asserted. The design's hierarchy is `rgba(ink, .35–.45)`; ink at `.45` over `#FCFBF9` measures **2.99:1** on 9.5 px text. Four compliant levels — 1.00 / 0.80 / 0.70 / 0.60 — preserve the ordering with a true floor of **4.58:1** on the dimmest light surface. Light gold text moves from the design's `#9A7B44` (3.84:1) to `#7D6539` (5.35:1 on the page, 4.70:1 on the dimmest container); the non-text gold stays `#AE8C4F`, so every rule, ring, and border on screen is still the design's exact gold and only small text is darkened. The design has no dark-theme danger colour and reusing its `#9C3B2E` measures 2.83:1, so dark gains `#D17466`.
- Three defects were found by building rather than by reasoning, each fixed at the source: twelve Material `…Fixed` colour roles were still holding Material's purple after the first pass, caught only because the role test was written reflectively; the Instrument Sans **variable** font would have silently collapsed the 400/500/600 hierarchy into one weight on API 26 and 27, because `fontVariationSettings` is honoured from API 28 while `minSdk` is 26, so three static instances are bundled instead; and the `INSIGHTS` tab clipped its last glyph at 200% font, found by installed-app capture and by no test.
- Two frozen decisions were amended by calibration rather than the code being bent to fit them: the light gold text token, whose first value `#886D3E` passes on `bg` and `card` and drops to 4.14:1 on `surfaceContainerHighest` — the rejection is now pinned by a test, because a token safe on only two of five surfaces will eventually be painted on the third — and light `onPrimary`, which became `bg` after the warm `onInk` measured 3.16:1 on gold.
- Deliberate structural choices, each because the obvious alternative would have been a behavior change: the design gallery is a **debug-only launcher activity**, not an `AppDestination`, because adding a destination is a navigation change; dialogs stay `AlertDialog` and gain only a container restyle, because the scrolling `AlertDialog` is what fixed the Phase 12 clipping defect at 200% font; the header keeps all three of its slots rather than adopting the prototype's single centred wordmark, because the app has a destination title and a Profile action that the prototype does not; and the prototype's initials avatar is out by definition rather than by taste, since it is a different Profile entry point.
- The 246 hardcoded dimension literals are deliberately **not** all retired at once. Rewriting numbers inside screen bodies a phase is not otherwise touching is a large untested diff whose only purpose is tidiness, and every such edit is a chance to silently drop one of the 158 testTags. They convert screen by screen, audited in Phase 18.
- Accepted consequence of the phasing, stated rather than discovered later: between this phase and Phase 18 the app is a correct foundation under unfinished rooms. The chrome is the design; the screen bodies still carry their pre-Phase-15 layout.
- Deferred with its own conditions: `intensityColor` is untouched. Moving it onto the prototype's single warm interpolation is a Phase 17 decision that must resolve the 0-versus-1 low-anchor difference explicitly and re-check `SPEC-track-numpad-logging.md` Invariant 14, because the light theme's warm low anchor `#F0E4CC` sits very close to the card surface.
- Honest gaps: spoken TalkBack output was not audited, only the semantics tree; the emphasis scale is proved by computation rather than by a human judging legibility on a real panel; Full Log, Insights, Settings, and Breathing were not individually captured, because their chrome is the same chrome Track exercises and their bodies belong to later phases; and the missing-font-resource fallback was not exercised, because a bundled resource cannot go missing without the APK being corrupt.
